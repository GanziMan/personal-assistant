# 개인 비서 AI — 아키텍처

> 대상: macOS (Apple Silicon) / 상시 상주형 개인 비서
> 구성: 클라우드 모델 중심 + 로컬 모델 보조, SwiftUI 메뉴바 프런트엔드

---

## 1. 설계 원칙

1. **도구층이 먼저, 모델은 나중.** 비서의 유용함은 모델 지능이 아니라 맥의 것들에
   손이 닿느냐에서 나온다. 모델은 교체 가능한 부품으로 취급한다.
2. **껍데기와 두뇌를 분리한다.** UI(SwiftUI 앱)는 두뇌(에이전트 데몬)와 로컬
   소켓으로만 통신한다. UI를 통째로 갈아엎어도 두뇌는 그대로다.
3. **선제성이 비서를 비서로 만든다.** 물어봐야 답하면 챗봇이다. 스케줄러와
   이벤트 워처가 먼저 말을 건다.
4. **기억이 없으면 매번 처음이다.** 대화·결정·문서를 3계층으로 축적한다.
5. **로컬 우선, 필요할 때만 밖으로.** 개인 데이터는 기본적으로 맥을 벗어나지
   않는다. 외부로 나가는 경로는 한 곳(라우터)으로 모아 감사 가능하게 만든다.

## 3. 컴포넌트별 책임

### 3.1 코어 데몬 (`core/`)

launchd로 로그인 시 상주하는 Python 프로세스. 비서의 실체는 전부 여기 있다.

| 모듈 | 책임 |
|---|---|
| `daemon.py` | 유닉스 소켓 서버, 세션 관리, 그레이스풀 셧다운 |
| `agent.py` | 에이전트 루프. 도구 호출/관찰 사이클, 토큰 예산, 중단 처리 |
| `llm/router.py` | 작업 종류에 따라 클라우드/로컬 모델 선택 |
| `llm/cloud.py` | Claude API 클라이언트, 프롬프트 캐싱, 재시도 |
| `llm/local.py` | Ollama/MLX 클라이언트 (임베딩·분류·요약 전용) |
| `tools/registry.py` | MCP 서버 연결·수명주기 관리, 도구 스키마 수집 |
| `memory/` | 3계층 기억. 아래 §5 |
| `scheduler/` | 선제 작업 정의·실행. 아래 §6 |
| `audit.py` | 모든 모델 호출과 도구 실행을 append-only 로그로 기록 |

### 3.2 MCP 서버 (`mcp-servers/`)

맥의 각 영역에 손을 뻗는 어댑터. 각각 독립 프로세스로, 하나가 죽어도
비서 전체는 살아있다.

| 서버 | 노출하는 것 |
|---|---|
| `macos-calendar` | EventKit 경유 일정·리마인더 조회/생성/수정 |
| `macos-files` | 지정 폴더 내 검색·이동·정리·메타데이터 |
| `macos-notes` | Notes.app, Obsidian 볼트 읽기/쓰기 |
| `macos-system` | 알림 발송, 클립보드, 앱 실행, Shortcuts 호출 |
| `dev` | 레포 탐색, git 상태, 테스트 실행 |
| `research` | 웹 검색·페치, RSS, 요약 파이프라인 |

### 3.3 SwiftUI 앱 (`app/`)

`MenuBarExtra` 기반 상주 앱. 두뇌를 갖지 않고, 소켓 너머 데몬에
말을 거는 얇은 클라이언트다.

- 메뉴바 아이콘 + 상태 표시(대기/생각중/알림있음)
- ⌥Space 전역 단축키 → 스포트라이트형 입력 HUD
- 스트리밍 응답 렌더링
- 알림 센터 연동, 데몬 상태 관리(재시작/로그)

## 4. 모델 라우팅 정책

라우터는 요청을 분류해 어느 두뇌로 보낼지 정한다. 기준은 비용이 아니라
**실패했을 때 사용자가 겪는 손해**다.

| 작업 | 경로 | 이유 |
|---|---|---|
| 임베딩 생성 | 로컬 | 양이 많고 품질 차이가 작다 |
| 텍스트 분류·라우팅 판단 | 로컬 | 짧고 반복적, 지연이 중요 |
| 짧은 요약 (한 문단) | 로컬 | 충분히 잘한다 |
| 다단계 계획·도구 사용 | 클라우드 | 로컬은 여기서 확실히 무너진다 |
| 코드 작성·리뷰 | 클라우드 | 품질 차이가 가장 크게 벌어지는 영역 |
| 민감 문서 처리 | 로컬 강제 | 정책으로 고정, 사용자가 예외 지정 |

라우팅 결정은 전부 감사 로그에 남긴다. "왜 이게 밖으로 나갔지"에
답할 수 없는 구간을 만들지 않는다.

## 5. 기억 설계 (3계층)

```
작업 기억 (Working)     현재 세션의 대화. 인메모리. 토큰 예산 내에서 유지
      ↓ 세션 종료 시 증류
일화 기억 (Episodic)    "무엇이 있었나". SQLite 이벤트 로그 + 임베딩
      ↓ 반복 패턴 승격
의미 기억 (Semantic)    "무엇이 사실인가". 선호·결정·인물·프로젝트 카드
```

- **저장소**: SQLite + `sqlite-vec` 확장. 별도 서버 없이 파일 하나로 끝난다.
  개인 규모(수십만 청크)에서 전용 벡터DB를 둘 이유가 없다.
- **임베딩**: 로컬 모델. 인덱싱은 양이 많아 클라우드로 보낼 일이 아니다.
- **검색**: 벡터 유사도 + BM25 하이브리드 → 재순위. 순수 벡터 검색만으로는
  고유명사·파일명 질의에서 자주 빗나간다.
- **승격 규칙**: 일화가 N회 이상 반복되거나 사용자가 명시하면 의미 기억으로
  올린다. 자동 승격은 보수적으로 — 잘못 굳은 기억이 제일 고치기 어렵다.
- **망각**: 모든 기억은 TTL과 신뢰도를 갖는다. 오래되고 참조되지 않은
  일화는 요약으로 접히고 원본은 아카이브된다.

## 6. 선제성 (스케줄러 + 워처)

| 트리거 | 동작 |
|---|---|
| 평일 08:00 | 아침 브리핑: 오늘 일정 + 밤사이 메일/RSS 요약 + 어제 미완료 할 일 |
| 매시 정각 | 임박 일정 확인, 30분 전 알림 |
| 금요일 18:00 | 주간 회고: 이번 주 커밋·완료 작업 요약 |
| Downloads 변경 | 임계치 넘으면 분류 제안 (자동 실행 아님) |
| 특정 레포 커밋 | 변경 요약을 일화 기억에 적재 |

원칙: **알림은 비싸다.** 선제 발화는 기본적으로 조용한 적재로 처리하고,
실제 알림을 띄우는 것은 화이트리스트로 관리한다.

## 7. 보안 경계

- API 키는 **macOS 키체인**에만. 설정 파일·환경변수·레포에 절대 두지 않는다.
- MCP 서버는 각자 허용 경로 화이트리스트를 갖는다. 데몬이 강제한다.
- 파괴적 작업(삭제, 덮어쓰기, 외부 전송)은 **확인 게이트**를 통과해야 한다.
- 감사 로그는 append-only, 로컬 보관.

## 8. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 코어 데몬 | Python 3.12 + uv | 에이전트/임베딩 생태계가 가장 두껍다 |
| IPC | Unix Domain Socket + JSON-RPC | 포트를 열지 않는다. 로컬 전용 |
| 저장소 | SQLite + sqlite-vec | 무설정, 단일 파일, 백업 쉬움 |
| 로컬 모델 | Ollama (+ MLX 선택) | 설치·교체가 가장 간단 |
| 클라우드 모델 | Claude API | 도구 사용 품질 |
| 프런트 | SwiftUI `MenuBarExtra` | 네이티브 상주 앱, 저메모리 |
| 상주 | launchd (LaunchAgent) | macOS 표준. 로그인 시 자동 기동 |

## 9. 구현 로드맵

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **P0** | 레포·문서·설정 뼈대 | 구조 확정, git 이력 시작 |
| **P1** | 코어 데몬 + 소켓 + CLI 클라이언트 | 터미널에서 대화가 된다 |
| **P2** | MCP 도구층 (캘린더·파일·시스템) | "오늘 일정 뭐야"가 된다 |
| **P3** | 기억 3계층 + 하이브리드 검색 | "저번에 그거"가 된다 |
| **P4** | 스케줄러 + 알림 | 아침에 먼저 말을 건다 |
| **P5** | SwiftUI 메뉴바 앱 | ⌥Space로 부른다 |
| **P6** | 로컬 모델 라우팅 | 임베딩·분류가 로컬로 내려간다 |
| **P7** | 다듬기 — 온보딩, 백업, 감사 뷰어 | 남에게 보여줄 수 있다 |

각 단계는 그 자체로 쓸 수 있는 상태여야 한다. P5까지 가야 처음 써보는
구조로 만들지 않는다.
